# Changelog

## Unreleased

- **DuckDuckGo is the main search engine by default.** The default mix is now about 70% DuckDuckGo (plus 2.5% its lite page), 12% Google, 4% each Bing and Brave, 3% Startpage and a trace of Ecosia, Mojeek and Qwant (it was a 35/35 split with Google). It applies to every profile that has not set its own weights in Settings > Search engines (which still wins); the old special case for one persona is gone because the default is now the same.

## v2.19.1

- **It keeps running: no failure limit, and a watchdog wakes it.** The "daily max failures" limit is gone: failed visits (a dead onion site, no network for a while) never pause or stop the noise any more, and the Settings control for it is removed (an old settings file that still has it loads fine, and it is ignored). Many onion visits failing in a row now make the app ask Tor for fresh circuits, then restart Tor if it still fails (at most once every ten minutes; a Tor that you share with Tor Browser is not restarted); a dead site is simply skipped and another tried, as before. New **Settings > Keep it running** (on by default, web and desktop): a watchdog checks every 30 seconds and (1) starts the noise again if it stopped on its own (at most six times an hour), (2) wakes it if it paused itself, and (3) restarts it if its main loop has not moved for 20 minutes (after the computer wakes from sleep it waits two minutes before judging). It never undoes a pause you pressed, never restarts after you pressed Stop, and respects your daily data limit (which ends at midnight). Turn the option off and a pause stays a pause. Tested with stand-ins for the run and the clock (a real week-long run was not tried).
- **Fix: hiding the menu (☰) no longer breaks the page.** The content was squeezed into a zero-width column and every word wrapped one letter per line; it now uses the full width. Checked in a browser (content 32 px wide before, full width after) and pinned by a test.

## v2.19.0

- **Fix (remote runner): the headless-browser lane now applies the same public-addresses-only rule as the plain HTTP lane**: a link found on a search page that pointed at a private, loopback or link-local address could previously have been opened by the browser. Checked on a real Chromium as an unprivileged user (the browser lane works; Chromium refuses to start as root, in which case the runner falls back to plain HTTP) and on a live HTTPS fetch.
- **Remote machines: run the noise on other computers you own, over SSH** (new Remote tab in the web dashboard and the desktop app, with the same features: add, test connection, trust a host key, start, stop, remove, status and a log for each machine). Give `user@host[:port]` and either a password or a private-key path (and passphrase). The app copies ONE stdlib-only runner (`remoteagent.py`, plus a settings file) into `~/.cache/legalprivacy` (Windows: `%LOCALAPPDATA%\\legalprivacy`) in that account, starts it over SSH and streams its log back; Stop ends it, Remove also deletes the folder. No root, no service, no display: a headless Linux machine works (a headless Chromium/Chrome/Firefox is used when one is installed, otherwise plain HTTP). It needs Python 3 on the machine. It makes that machine's own page visits (with follow-up links and page assets), searches, DNS lookups and downloads (read and thrown away, never saved to disk). Every start draws fresh random settings per machine: its own browser identities and when they change, rhythm (bursts and quiet gaps), daily peak hour, lane mix, hourly and daily budgets, and a different slice of sites and searches, so no two machines (or two starts) share a schedule. The runner never connects to private, loopback or link-local addresses (also after a redirect), has hard ceilings on rate, data and download size, and stops when the SSH connection ends. **Safety:** only for machines you own or are authorised to use (the UI and the API require you to say so); host keys are checked BEFORE any password or key is sent, a first-seen key is shown as a fingerprint and trusted only when you confirm it, and a changed key is refused, never accepted silently (you must forget the old one first); passwords and passphrases live in memory only (never saved, logged or shown; a key path is saved, never the key); Panic and quitting stop the remote runners. `paramiko` is an optional dependency (`pip install legalprivacy[remote]`); without it everything else works and the tab says what to install. Linux is the tested target; Windows OpenSSH/PowerShell is built for but only exercised against a fake machine.
- **Weekly rhythm.** "Adjust to my rhythm" now keeps weekdays and weekends apart: on a Saturday or Sunday it uses what the observer recorded of your weekends, on other days your weekdays (each needs about 20 recorded minutes in at least four hours; until then it uses all days together, and the Proof tab says which). The observer keeps 7 days, so a weekend's record is two days of data and is rough at first. Not done: a different rhythm for each of the seven days.
- **Desktop app catches up with the web dashboard.** Settings > **Logo**: pick the header logo (red, white and blue by default; four other traditional ones) and optionally let it change as you change tabs; the choice is saved. Tools > **Block a site for the noise**: type a site to leave it alone for a day or always (and unblock it), or an IP address to get its reverse name, an owner lookup link and firewall commands to copy; the web dashboard does the same by clicking a bubble on the network map. The Proof text already showed p-values and the automatic correction. Not tested on screen: this sandbox has no Tk, so the new desktop controls are covered by tests of their logic and files only; please look at them.

## v2.18.0

- **File transfers as noise** (`files.py`; Settings "File transfers", on by default, web and desktop): now and then, on its own schedule like the DNS and package noise, the app downloads a real public file and throws the bytes away, or uploads a random-sized block of random bytes. Downloads come from the Internet Archive's free collections found through its search API: Flickr Commons photos (most of them), Prelinger films, Project Gutenberg zips and documents, and open-source audio, so the file types lean the way real use does. Sizes vary a lot (log-normal, median about 1.5 MB, each download capped at 20 MB and the transfer stops at the cap); uploads send 10 KB to 3 MB of random bytes to Cloudflare's public speed-test endpoint and never anything of yours. Budget 10 transfers a day; skipped in low-data mode and counted in the daily data cap. **Over Tor:** file links that onion pages offer (images, documents, archives, audio) are collected, and now and then one is downloaded through Tor (8 MB cap). Checked against the real Internet Archive from my sandbox (images, video, archives and documents found and a photo and a book downloaded; the audio query found nothing that fit under the cap that time) and the Cloudflare upload (HTTP 200). Not done: visiting file-sharing sites; ordinary web file downloads through Tor are not done because ordinary noise never goes through Tor.
- **Network map: click a bubble.** A panel under the map shows what it is and offers **Info** (address, reverse name, who owns it via a link to bgp.he.net that opens in a new tab), **Block this site (a day)** and **Block always** (the noise then leaves that site alone; undone with unblock), and **Firewall commands** (nftables, iptables, ufw and Windows netsh, each with its undo) to copy. The app cannot change your firewall itself: that needs administrator rights, so a real firewall block is a command you run.
- **Fix: the release build and CI could fail on random tests** that did not seed their random draws (two duck.ai tests); they are seeded now. The executable build also collects every `legalprivacy` module, so a lazily imported one cannot be missing.
- **Scrape a site** (Tools tab, web and desktop; `scrape.py`): a polite spider for jobs you start. Tables become CSV files; images, video, audio, documents and archives are saved to a folder under the app folder (limits per file and per job). It follows robots.txt, stays on the start site, waits a random few seconds between requests, and can **mix in noise**: now and then it visits an unrelated popular site between its own requests so the job does not arrive as one unbroken run. It can go through a proxy that passed the proxy tester. It reads only what a visitor can see: no logins, no challenge solving. Checked against a local test site (tables, images, video, documents, robots.txt, file-size limit, stop button) and in a browser; not tried on real sites.
- **Tested free proxies** (Tools tab, web and desktop; `proxies.py`): fetches public proxy lists (seven GitHub raw lists by default, each checked to exist, plus any web page you add: every `ip:port` on it is picked out), tests each candidate with a real HTTPS request to a known test page, and throws out the dead, slow (over 2.5 s), wrong-answer and transparent ones at once; one that worked before gets one more try, then goes, and kept ones are re-tested every few hours. Used only for jobs you start (the scraping tools are not built yet), never for the noise or logins; the card says free proxies are run by strangers and can read plain traffic. Checked: the lists download and parse (about 11,000 candidates) and the tester logic passes tests with stand-in proxies; I could not test against real proxies from my sandbox (its network blocks them), so the keep rate on your connection is unknown.
- **Menu**: the web menu now lists each tab's cards under the tab you are on (Settings, Tor, Tools, Proof, Help: click one to jump to it), every page has a title that matches its menu label, and the ☰ button hides the menu completely (Collapse keeps the icons). The **Security** tab is now called **Antivirus** everywhere (menu, page, desktop app, messages), because it is the ClamAV page. **Help** is now a set of expandable sections (What this does, Getting started, Look like yourself, Tor, Antivirus, Menu and shortcuts, About).
- **Proof tab: p-values, and it now corrects what it finds.** Each rhythm comparison (time of day, burst length, quiet gaps, busyness) shows the similarity, the percent difference and a p-value (Kolmogorov-Smirnov; minutes next to each other are not independent, so treat p as a rough guide, not a verdict).
- **"Adjust to my rhythm"** (Settings, web and desktop; on by default): from what the observer recorded of your own traffic, each hour of the day gets a multiplier on the planned noise, up to twice as much in the hours you are away and down to half in your busy ones, so the traffic an observer sees (yours plus the noise) is about as busy at every hour. The Proof tab lists the hours it is changing. Needs about 20 recorded minutes in each of at least four hours of the day. Not done: bursts and busyness within a minute are shaped by the rate only, not directly.
- **Searches come in related runs** (`narrative.py`): after a search, an identity often goes on with follow-ups on the same topic (a narrower term, "best", "reviews", a year, "X vs a related query"), instead of every search standing alone. Researchers separated query noise from real searching by clustering queries by meaning, which is what this closes. The follow-ups keep the origin of the search they follow, so the persona share is unchanged. In 200-query runs the related-word overlap between neighbouring searches is clearly higher than before (tested).
- **Chat noise on duck.ai** (off by default; Settings, web and desktop): in a long session on duck.ai, the real-browser lane has a short made-up chat: one topic taken from the same sources as the searches, one to four messages of different lengths (the size and timing of a chat's traffic follows what is sent and returned, so a fixed shape would be a pattern), typed like a person, each reply waited for and read. Nothing comes from you. **Switching it on accepts duck.ai's terms screen for you**; without it the page is only visited. duck.ai may limit or block automated use. Checked against a stand-in chat page, not against duck.ai itself.
- **Fix**: `long_sessions`, `multi_tab` and the new `duck_chat` were reset to their defaults whenever any extras setting was saved; they are now kept.
- **Busier levels**: searches an hour by level are now 1, 2, 4, 7, 11, 17, 25, 36, 50, 70 (level 9 was 15, now 50); random mode still goes well above that in busy hours. The per-engine limit is 20 searches an hour (was 8); above it searches spread over more engines.
- **Mix of activity vs background**: DNS lookups and package installs run alongside the activity mix and never took a share of it; the desktop app now shows them as their own amounts (as the web dashboard already did). DNS defaults to **More** (3x searches + link-following); a new **Lots** step.
- **DNS bursts are visible**: each lookup's page-load burst is listed with it in Activity and the Live Log.
- **More randomness**: searches, link-following, DNS and installs each wander on their own every hour; the burst, click-through and search-first chances vary a little each time.
- **Long sessions no longer hold up the rest**: most run alongside everything else; about 1 in 8 (itself varied) takes over the way it used to.

- **User agent: Mix is the default**, 85% your own browser's user agent. **Browser engine** choices renamed so it is clear which is your own Firefox and which are the app's copies; with your Firefox, the share of the noise that isn't your user agent, and phones, run in the app's own browsers. Your Firefox's window is never maximised.

- **Recommended settings check** (Health): compares the human-like behaviour switches (long sessions, second tab, DNS bursts, DNS in the browser, cookie lifetime, user agent mix) with the recommended values and offers a one-click "Use the recommended ones" that changes only those, never your sites, personas or limits.

## v2.17.0

- **Fix: Tor Browser opened from the app could not load any page.** The app started it with `TOR_TRANSPROXY=0`, but Tor Browser only checks that the variable exists; it then switches its own proxy off (no SOCKS address at all) and every page fails. Reproduced and fixed on a real Tor Browser 16.0.3: it now ends up with SOCKS on this app's Tor, Safest security level and the 37 onion bookmarks on its toolbar.
- Health tab (and a banner on the Dashboard) now strongly recommend Tor bridges and Tor DNS when Tor is on, and say how your own lookups can be kept private (encrypted DNS in your browser or system, or Tor DNS); each recommendation has a one-click fix (built-in obfs4 bridges, Tor DNS on, DNS noise back to Mix, or switching Tor on). Fixes apply to saved settings; restart Tor to apply.
- Tor Browser (opened from the app) now starts at security level **Safest** (`browser.security_level.security_slider` = 1, set in the profile's user.js at every launch; you can still lower it for a session from the shield button), and every known onion site is a named bookmark on its bookmarks toolbar (Firefox's `Bookmarks` policy in `distribution/policies.json`; other policies already there are kept). The 37 built-in sites all have names; sites from your own onion list are named by what their page calls itself (read from the pages the noise visits) or, until then, a short form of the address. The files are rewritten each launch and are not part of the signed program files, so the signature re-check is unaffected.
- Tor Browser shares the app's Tor **by default** (existing installs are moved over once; turn it off on the Tor tab). Opening Tor Browser now starts the app's Tor first when it is not connected, checks that Tor Browser's door into it really answers (and says so if not), starts Tor Browser with the original library path in the packaged app (the bundled one made it unable to connect), and keeps what it prints in `torbrowser.log` in the app folder. The noise no longer sends NEWNYM under a shared Tor Browser.
- Relay screens (web and desktop): no contact address any more (it would be published; nothing is sent even from an older saved one), a nickname that starts as "legalPrivacy" plus four random characters (the old app's name is replaced once), info hovers for nickname, speed limit, ORPort and practice mode, the checklist boxes ticked by default, and the form stays editable while a relay runs (the button becomes "Restart with these settings"; before, everything was locked, which is why the boxes would not tick).
- HTTP parity (plain-HTTP lane): its requests now carry the headers of a real Chromium page visit in Chromium's own order, measured against Chromium 153 over HTTP/1.1 (before, `requests` put its own User-Agent, Accept-Encoding, Accept and Connection first, used a shorter Accept and left out Sec-Fetch-User). Visits reached by a click send Sec-Fetch-Site as same-origin, same-site or cross-site and a Referer as Chromium would (whole address within a site, only the origin to another, none from https to http). Accept-Encoding lists only what can be decoded; install the optional `parity` extra (`pip install legalprivacy[parity]`, brotli and zstandard) to say "gzip, deflate, br, zstd" like a current browser. Not covered: the TLS fingerprint and HTTP/2, which need a different HTTP client (the plain lane is off by default).
- Desktop app: the Tor tab now has the Tor Browser card the web dashboard already had: Open (or install and open) Tor Browser, Check for updates, the signature line, and "Share this app's Tor with Tor Browser" so your own browsing and the noise use the same Tor. The plain-text name beside the header logo is gone.
