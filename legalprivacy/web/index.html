Bridges
ⓘ
Bridges are unlisted entry points into Tor. You only need them if your network blocks Tor or you don't want your provider to see that you use Tor. obfs4 disguises Tor as random-looking traffic; Snowflake goes through volunteers' browsers and looks like a video call; meek looks like ordinary visits to a big website (slow). The built-in ones come with the official Tor bundle and are shared by many people, so they get blocked more often than your own.

Request your own private bridges: website · Telegram @GetBridgesBot · email bridges@torproject.org (from Gmail or Riseup). Paste them above and choose “My bridges”.

Tor DNS (optional)
ⓘ
Tor can answer DNS lookups on a local port. Names are looked up by Tor exit relays, so this is a deliberate, narrow use of exits for DNS only. It does not change the Tor lane for noise, which stays onion-only. Only A (IPv4), AAAA (IPv6) and PTR (reverse) lookups work; other kinds, such as MX or TXT, are not handled.

Sends one real lookup for example.com through Tor and shows the answer and how long it took.
Address
Warning. Anyone on that network can use your Tor exits for DNS, and you are responsible for what they do. Never expose this to the internet; it is not an open resolver for the internet. Only share it on a network you trust, such as your own home.
How to use it

Your operating system sends DNS lookups to port 53, so it cannot use this port directly. To use Tor DNS for the whole computer you need a small local forwarder (for example dnsmasq or unbound) set up to forward to 127.0.0.1 and the port shown above, or an app that lets you set a DNS port yourself. The commands differ by system and we have not verified any, so none are given here; follow your forwarder's own documentation.

Tor DNS is slower than normal DNS (every name goes through Tor and an exit relay) and handles only A, AAAA and PTR lookups.

Tor Browser: for your own private browsing
ⓘ
Opens the official Tor Browser so you can browse privately yourself. It is completely separate from the noise: its own folder, its own profile and its own Tor. The app downloads it only from torproject.org and installs it only after checking its signature with the Tor Project's signing key (this needs GnuPG, "gpg"). It is brought up to date whenever you open it from here, and it is never started as the administrator.

Relays to avoid (optional)
ⓘ
Tor picks relays you cannot vet. If you know of relays or whole countries you do not trust, list them here and the app's Tor will avoid them for every step it can, including looking up onion addresses. One per line: a relay's 40-letter fingerprint, or a country in braces such as {ru}. Lists published by network researchers can be pasted in. Without "strict", Tor may still use them if it cannot connect otherwise.

Saved with the other Tor settings. Takes effect the next time Tor starts.

Contribute to Tor: run a relay (optional)

A relay passes other people's encrypted Tor traffic along, which helps the network. It is not an exit: it never connects to websites for anyone, and legalPrivacy can never make it one. A relay or bridge also does not provide DNS (only exit relays look up names). Relay addresses are public by design: the Tor network publishes them in a list anyone can read. The relay runs as its own separate Tor program; it never starts by itself.

Router and firewall notes

All systems: a public relay must be reachable from the internet on its ORPort (TCP). Forward that port on your router to this computer, then allow it in the computer's firewall. Router menus differ; look for "port forwarding" or "virtual server".

Windows: allow the port in Windows Defender Firewall (Inbound Rules). macOS: if the firewall is on, allow incoming connections for the Tor program. Linux: allow the TCP port in your firewall (ufw, firewalld or nftables).

The status shows "reachable" only after Tor itself tests the port from outside, which can take a while for a new relay. See the Tor Project's relay documentation: community.torproject.org/relay.

Realism

Browse with a real browser
A real Chrome/Edge/Chromium scrolls, pauses to read, moves the mouse, clicks or taps search results and now and then downloads a file (discarded). Plain HTTP can't do any of that and is easier to spot.
Browser engine
Each engine has its own network fingerprint. Mixing uses Chrome-style and Firefox-style browsers together, the way many different people browse (each noise identity keeps one browser). Matching yours only makes the noise look like you. Firefox needs a one-time download (python -m playwright install firefox); without it, Chromium is used. Firefox can't emulate phones, so phone visits run as desktop with it.
Browser window
Hidden never shows a window. When visible, the noise browser uses one window and opens its pages in tabs.
Keep the noise browser's cookies
ⓘ
There's no perfect answer. Cookies are how sites track you, so keeping them long lets the noise build a profile. But a browser that never keeps any looks like a brand-new visitor every time, and sites ask “are you a robot?” far more often. A short life (about an hour) gets most of the benefit with little tracking. With “vary it a little”, each set of cookies lives 60–140% of the time you choose, so the resets don't happen on a fixed beat. These are legalPrivacy's own cookies, never your browser's.
Hidden runs the same Chrome code as a normal window, and what your ISP or DNS provider sees is identical. Only a site's own scripts, checking deeply, can tell (for example, no graphics card). Off-screen uses a real window and real graphics where no screen shows it: a little more realistic to those scripts, but uses more CPU and memory. Visible is for watching.

Accounts (optional, off by default)
ⓘ
Lets the noise browser browse while signed in to your own Google and Microsoft accounts, so the noise looks like a logged-in person. You sign in yourself, in a normal browser window that opens on this computer; legalPrivacy never sees, stores or types your password or a code. Only the browser's session (cookies) is kept, in legalPrivacy's own folder with owner-only permissions, apart from the ordinary noise browser's cookies. Signed-in visits only load and scroll a few pages (a Google search, the Gmail inbox, YouTube; the Outlook inbox and calendar, Bing, microsoft.com). They never click, open a message, send, delete, archive, label, mark, reply, forward, accept or decline, sign out or change a setting. They go through the normal internet connection, never through Tor. Panic (medium and hard) deletes these sessions. 429 means a site answered “too many requests, slow down”; a robot-check page is the site asking whether you are a person. Either one, or a sign-in page, pauses that account's signed-in visits for a random while (hours; longer if it keeps happening) and the ordinary noise carries on.

Please read: these are your real accounts. The searches and visits become part of that account's history and affect its ads and recommendations. Google or Microsoft may ask you to verify, or restrict, an account that looks automated. A spare account is safer. Nothing is ever sent, deleted or changed in the mailbox.
This computer has no display, so a sign-in window can't open here. Sign in from a computer with a screen.

Panic
ⓘ
Stops the noise right away. Medium also clears the log and the noise browser's cookies, and deletes any signed-in account sessions (Accounts above; you would have to sign in again). Hard also does all of that, stops Tor and deletes what legalPrivacy recorded about connections (the Proof tab data) and its log files. Your settings are never deleted, and nothing outside legalPrivacy's own folder is touched.

What this does

legalPrivacy makes believable searches, page visits and DNS lookups in the background, so that bulk analysis of your real browsing tells much less about you. Every request shows in Activity; everything the app and Tor report is in Live Log. Both are kept in memory only and cleared when you quit.

Activity vs Live Log. Activity lists each request the noise made and what happened on it. Live Log is everything the app says, including starts and stops, Tor's own messages and warnings.

Getting started. Everything already has the recommended setting. Press Start; the first action comes within seconds. Settings save themselves.

Look like yourself. Add the sites you really use on My List, then check the ML tab: it shows how easily your traffic can be told apart from the noise, and which settings help.

Tor (optional). Off by default. With Tor on, legalPrivacy can visit .onion sites through its own private Tor, which it downloads, checks and starts for you. Many .onion sites are offline at any moment; those are skipped for a while, which is normal. Ordinary web noise never goes through Tor; the Tor lane visits only .onion sites.

Contribute to Tor. legalprivacy relay gen writes a middle-relay or bridge configuration; it never runs an exit. The Tor tab has two optional cards, both off by default: Tor DNS (Tor answers A, AAAA and PTR lookups on a local port; exit relays resolve the names, so it is slower and is a deliberate, narrow use of exits for DNS only) and Contribute to Tor: run a relay (a middle relay or bridge as a separate Tor program; start with Practice mode, which publishes nothing). A relay is not an exit and does not provide DNS.

Antivirus (optional). The Security tab manages the ClamAV you installed yourself, offline-first. Only freshclam, the signature updater, ever contacts the internet, and only when you press Update and confirm. Scans use clamscan with this app's own signature folder, with the network removed where the system allows it (Linux) and the scanner watched for any connection everywhere; a connection marks the scan NOT OFFLINE and stops it. Nothing is ever deleted or moved except by your explicit Quarantine click.

The dashboard is reachable only from this computer (127.0.0.1) and needs the token in its address.

Can your traffic be told apart from the noise?

A classifier tries to separate your real browsing (your browsers' history, read on this computer only) from the noise, using only what your ISP or DNS provider could see: the hour, weekday, rhythm, how popular each site is, revisits and domain endings. Its ROC AUC is the score: 50% means it can't tell them apart, 100% means it's trivial. Nothing is sent anywhere; only the scores are kept.

Stays offline

What contacts the internet, how that is prevented, and how it is checked.
